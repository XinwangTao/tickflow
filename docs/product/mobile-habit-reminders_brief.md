# Android 习惯提醒简报（L2）

- 目标：手机端到点收到习惯提醒，体验与桌面一致；提醒时间随 R2 同步。
- 范围 In：每习惯一条每日提醒时间；保存到 IndexedDB（复用 `habitReminders` 同步字段）；通知权限申请；注册/取消/重排本地通知；启动、升级、时区变化后对账；权限或渠道异常提示。
- 范围 Out：任务提醒、每日多次提醒、稍后提醒、通知中心历史、iOS、共享/协作。

## 成功标准

1. App 在后台或锁屏时，到点收到系统通知（每习惯每天一次）。
2. 改时间立即生效；关闭提醒或删除/归档习惯后不再触发。
3. 杀进程后仍按时触发；系统重启后恢复调度。
4. 通知权限被拒绝时给出可恢复提示，不阻塞打卡。
5. 不重复通知；跨时区不偏移到错误日期。

## 主路径

1. 习惯列表 → 设置提醒时间 → 检查/申请通知权限 → 注册每日通知 → 到点触发。
2. 修改/关闭提醒 → 取消旧通知 → 注册新时间或保持关闭。
3. App 启动/升级 → 读取本地提醒 → 与系统待触发列表对账 → 重排缺失项。

## 失败与人工出口

- 权限拒绝：显示「去设置开启通知」，保留已存时间，下次进入可重试。
- 通知渠道被系统关闭：提示渠道状态，不静默失败。
- Android 12+ 精确闹钟限制 / 省电模式：允许系统延迟，界面注明可能晚到。
- 系统重启：启动对账重排；若系统未触发，进入 App 后自愈。

## 约束与借鉴

- 现有栈：Capacitor 8.6 + React + Dexie；插件选 `@capacitor/local-notifications` 8.3.1（peer `@capacitor/core >=8`）。
- 插件能力：`checkPermissions/requestPermissions`、`schedule`（daily repeat + `allowWhileIdle`）、`getPending`、`cancel`；Android 13+ 需 `POST_NOTIFICATIONS`。
- 借鉴：沿用桌面「每习惯每天一次 + HH:MM」模型和已同步的 `habitReminders` 结构；UI 与存储自研，不引入第二套提醒模型。

## 待确认假设

1. 每习惯仅一条每日提醒，不做多次或自定星期。
2. 关闭提醒写 tombstone（已实现于同步范围），并取消系统通知。
3. 通知点击打开「更多 → 习惯」。
4. 安卓端不建通知中心历史，只保留系统通知。
5. 权限被拒绝时不代用户反复弹窗，只在习惯页提示并提供重试。

## 真机待办（无法本机验证）

- 锁屏/后台到点、杀进程后到点、系统重启后到点。
- 权限拒绝后恢复、通知渠道关闭提示。
- 省电模式/厂商后台限制下的实际延迟。
- 跨时区（手动改时区）后的触发时间。
