# 刻度清单 TickFlow — 产品简报（L2）

- 状态：**待确认**（Archify C 阶段，确认后才写业务代码）
- 日期：2026-11-05
- 参考样本：本机滴答清单 Windows 客户端（`E:\APP\滴答清单`，.NET/WPF + SQLite + WebView2，2026-11-05 黑盒盘点）
- 目标平台：Windows 桌面（Electron + React + TypeScript + SQLite）
- 后续平台：Android + 桌面/手机同步（**不使用 Cloudflare R2**）
- 还原边界：布局、交互、信息密度、快捷键尽量对齐；**商标、图标、插画、文案库、代码全部原创，不复制对方素材**

## 1. 用户与问题

用户需要一个本地优先、离线可用、界面与滴答清单高度接近的任务管理桌面应用，覆盖清单、任务、日历、四象限、看板、习惯、番茄、统计等完整单机功能；后续扩展到 Android，并在设备间同步，但同步不依赖 Cloudflare R2。

### Out of Scope（首版不做）

- 账号体系、云同步、协作/共享清单、评论

## 3. 主路径场景（验收用）

1. 快速添加 `明天下午3点 交周报 #工作 !高` → 任务进入「最近 7 天」，标签/优先级/提醒正确，列表与日历同步出现。
2. 在清单中新建任务 → 设置「每周一」重复 → 完成后按规则生成下一次；撤销可恢复。
3. 日历月视图拖拽任务改期 → 列表、今天、四象限同步更新，重启后仍生效。
4. 习惯打卡 → 连续天数、热力图、统计更新；漏打卡不误算。
5. 番茄钟关联任务专注 25 分钟 → 记录会话，任务详情与统计可见。

## 4. 关键失败 / 人工兜底

- **数据库损坏或迁移失败**：启动时检测 → 自动使用最近备份 → 仍失败则只读模式 + 明确提示 + 手动选择备份。
- **提醒错过（应用未运行）**：启动时汇总「错过的提醒」弹窗，可逐条稍后/完成/打开任务。
- **导入冲突/重复**：先预览差异，用户选择合并/跳过/覆盖，不静默写入。
- **附件丢失**：任务详情显示占位与「重新关联」，不阻塞任务本身。

## 5. UI 结构（黑盒盘点，仅借鉴布局）

- 左侧 48px 图标栏：头像、任务、日历、四象限、番茄、习惯、搜索；底部同步、通知、帮助。
- 第二栏约 200px：今天、最近 7 天、收集箱；清单分组；标签；过滤器；已完成、已放弃、垃圾箱。
- 主内容区：视图标题 + 计数 + 更多菜单；`+ 添加任务` 输入；置顶区；任务分组（已完成/已放弃可折叠）。
- 任务行：复选框、标题、日期/重复/清单/优先级元信息；悬停操作。
- 深色近黑背景、紧凑 13px 字号、细分割线、低饱和强调色；浅色主题同构。

## 6. 技术方案（草案）

- **桌面壳**：Electron（主进程负责窗口、托盘、全局快捷键、通知、单实例、文件与 SQLite）
- **前端**：React 18 + TypeScript + Vite；Zustand 状态；CSS Modules + 设计令牌（不用通用 Tailwind 默认风）；Radix 无头组件保证可访问性；Framer Motion 做轻量动效；dnd-kit 拖拽
- **数据**：`node:sqlite`（Electron 45 自带 Node 24，无需 native 编译）+ 版本化迁移 + 参数化 SQL；主进程持有数据库，渲染进程通过 `contextBridge` 的类型化 IPC 访问
- **富文本**：P1 用原生 textarea，P2 接 Tiptap；**日期**：自研轻量工具 + rrule（P2 重复任务）；**自然语言**：自研中文解析器（相对日期/周几/时间/#标签/!优先级/~清单/常见重复）；**图表**：Recharts（P3）
- **测试**：Vitest + React Testing Library；Playwright 做 Electron 冒烟；**打包**：electron-builder（NSIS）
- **同步就绪设计**：所有实体使用 UUIDv7、`created_at/updated_at/deleted_at`、`device_id`；本地 `change_log` 记录变更（seq/entity/op/payload）；同步层抽象为 `pull(since)/push(ops)/resolve()`，首版不启用
- **同步路线（P5 再定，不用 R2）**：自建轻量同步服务（Node/Go + SQLite/Postgres + WebSocket，部署在自有机器/NAS/VPS，远程走 Tailscale）或纯局域网直连；Android 端优先评估 Capacitor 复用 React，若移动体验不足再转 Kotlin/Compose

## 7. 借鉴调研（1 回合）

- **借鉴**：Super Productivity（Electron 本地优先、时间跟踪）、Vikunja（列表/看板/日历、自建同步）、Tasks.org（Android + CalDAV）——均只借鉴架构与交互模式。
- **自研**：滴答清单式的紧凑图标栏 + 智能清单 + 四象限 + 习惯/番茄统一数据模型；中文自然语言快速添加。
- **不采用**：Cloudflare R2、账号强依赖、复制滴答清单任何素材/代码/文案库。
- **对架构的直接影响**：① SQLite + change_log 的 local-first 设计；② Electron + React + 类型化 IPC；③ 领域逻辑独立成 `packages/core`，为后续 Android/Capacitor 复用。

> 说明：以上为公开项目常识级调研，未逐仓库核验最新实现；不影响本阶段架构决策。

## 9. 成功标准

- Windows 安装包可启动，无控制台错误；冷启动 < 2s（1 万任务库）。
- 任务全字段持久化，重启/崩溃恢复不丢数据。
- 日历拖拽改期、四象限分组、看板拖拽、批量操作、撤销均正确。
- 提醒在应用运行期间误差 ≤ 30s；错过的提醒启动时可见。
- 1 万任务标题/备注/标签搜索 < 200ms。
- 导入导出 JSON 往返一致；ICS 可被主流日历读取。
- 浅色/深色主题完整；键盘可完成主要操作；无素材/商标侵权。
