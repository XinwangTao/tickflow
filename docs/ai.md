# TickFlow AI 能力

TickFlow 的 AI 能力全部在 **Electron main 进程**发起请求，renderer 只通过 IPC 调用。
默认对接本机 [CC Switch](http://127.0.0.1:15721) 的 Anthropic 兼容网关，不依赖任何云端密钥。
AI 只提供增强：超时、服务未启动、模型报错或返回结构非法时，立即回落到本地规则，
不会阻塞任务创建或界面操作。

## 1. 默认配置与开关

设置入口：右上角「设置」→「AI 助手（CC Switch）」。

| 设置键 | 默认值 | 说明 |
| --- | --- | --- |
| `aiEnabled` | `true` | AI 总开关。关闭后不发起任何请求，快速添加走规则解析，AI 入口隐藏 |
| `aiBaseUrl` | `http://127.0.0.1:15721` | 网关地址；也兼容填到 `/v1`，客户端会自动补全 `/v1/messages` |
| `aiModel` | `ccs-claude-openai--ccs-claude-openai-2--glm-5.3-flash` | 必须与 `/v1/models` 返回的 `id` **逐字一致** |
| `aiToken` | 空 | 可选。非空时同时发送 `x-api-key` 与 `Authorization: Bearer` |
| `aiTimeoutMs` | `15000` | 单次请求超时；范围 1000–120000 毫秒 |

设置保存在本机 SQLite 的 `settings` 表，Token 不会上传或写入日志。

设置页「模型 ID」右侧提供 **获取模型列表**：点击后请求本机 `GET /v1/models`，
把返回的 `id` 原样放进下拉框，避免手工抄写出大小写或分隔符错误。若当前填写的
模型不在目录中，设置页会给出提示。

加载期间按钮显示「获取中 Ns」已等待秒数，旁边出现 **取消**：中止那次 `fetch` 后提示
「已取消获取模型列表，当前模型配置未改变」，不再等待超时，也不会把迟到的目录塞进下拉框。
关闭设置页（组件卸载）时同样会静默中止进行中的目录请求。目录请求失败时 toast 提供
**重试**，网络恢复后无需重新打开设置页；瞬时故障仍会自动重试 1 次，提示里会标注次数。

### 查看本机可用模型

```bash
curl -s http://127.0.0.1:15721/v1/models \
  -H "anthropic-version: 2023-06-01"
```

也可以直接在设置页点「获取模型列表」，无需手动执行命令。

当前环境验证可用的示例 `id`（直接照抄，不要改大小写或分隔符）：

- `ccs-claude-openai--ccs-claude-openai-2--glm-5.3-flash`（默认，低延迟）
- `ccs-claude-openai--ccs-claude-openai-2--glm-5.3`
- `ccs-claude-openai--ccs-claude-openai-2--kimi-k2.7-code`
- `ccs-claude-openai--ccs-claude-openai-2--deepseek-v4.1-flash`
- `ccs-claude-openai--ccs-claude-openai-2--qwen3.8-max`

## 2. 接口约定

客户端实现：`src/main/ai-client.ts`。所有功能共用 `POST {baseUrl}/v1/messages`。

请求头：

```http
content-type: application/json
anthropic-version: 2023-06-01
x-api-key: <aiToken，可选>
authorization: Bearer <aiToken，可选>
```

请求体（Anthropic Messages 格式）：

```json
{
  "model": "ccs-claude-openai--ccs-claude-openai-2--glm-5.3-flash",
  "max_tokens": 1200,
  "temperature": 0.1,
  "system": "你是任务管理应用 TickFlow 的解析器。你只输出严格 JSON。",
  "messages": [{ "role": "user", "content": "<提示词>" }]
}
```

响应解析兼容 `content: [{ type: "text", text: "..." }]`，会忽略 thinking 块；
也兼容 OpenAI 风格的 `choices[0].message.content` 与纯字符串 `content`。
模型返回的 Markdown 代码块或前后解释文字会被容忍，客户端只提取第一个 JSON 值。

不同功能的 `max_tokens`：快速添加 1200、子任务拆解 1600、今日总结 1600、测试连接 768。
推理模型会先用掉一部分 token 输出 thinking，预算过小时可能只有 thinking、没有正文；
如果响应 `stop_reason` 为 `max_tokens`（或 OpenAI `finish_reason` 为 `length`）且没有
正文，客户端会提示「AI 只返回了推理过程，正文为空（输出预算不足）」，而不是笼统地报空。

非 2xx 响应会抛出 `AI 接口返回 <status>：<前 200 字符>`；超时抛出 `AI 请求超时`。
错误信息最终只用于 toast 与降级原因展示，不会中断操作。

### 模型目录

`GET {baseUrl}/v1/models`，请求头同上。客户端兼容 `{ "data": [...] }` 与纯数组，
只读取 `id`（逐字保留）与可选的 `display_name`，去重后最多返回 200 个。
非 2xx 返回 `AI 模型列表返回 <status>：<前 200 字符>`，超时返回
`AI 模型列表请求超时`；设置页会把这些信息直接展示在 toast 中，并提供「重试」。
目录请求同样支持 `ai:cancel` 的 requestId（`models-N`），用户取消时返回
`已取消获取模型列表`，与失败提示分开。

「测试连接」会发送一条 `max_tokens: 768` 的最小请求。推理模型会先输出 thinking
块，预算过小时可能只有 thinking 没有正文，从而误报失败；768 能为 thinking + 简短回复
留出余量，且 `max_tokens` 只是上限，不会强制生成更多内容。

## 3. 三个首批功能

### 3.1 AI 自然语言快速添加

入口：今天 / 最近 7 天 / 收集箱 / 清单视图顶部的快速添加框。

- 普通 `Enter`：始终使用本地 `parseQuickAdd` 规则，零延迟。
- `Ctrl/Cmd + Enter` 或点击输入框右侧 **AI** 按钮：把整句话交给 AI 解析。
- AI 输出字段：`title`、`dueDate`（YYYY-MM-DD）、`dueTime`（HH:mm）、`allDay`、
  `priority`（0–3）、`tags`、`listName`、`recurrence`（RFC5545 RRULE）、
  `reminderMinutes`（提前提醒的整数分钟，没有则为 null）。
- AI 成功时**不会立即写库**，而是在快速添加框下方展开「AI 解析结果 · 可修改后添加」
  草稿卡：标题、截止日期、时间、优先级、清单、标签、重复、提醒、全天都可以改，
  点「添加」或标题框回车才创建任务；点「取消」/`Esc` 放弃本次结果，输入内容仍保留。
  草稿会经过 `draftToQuickAddResult` 再校验一次，非法日期/时间只丢弃该字段。
- 用户主动清空日期时，创建任务不会被当前视图的默认截止日期补回来
  （例如「今天」视图的 AI 草稿删掉日期，任务就是无日期）。
- 添加成功后 toast 显示「AI 已添加「标题」」并提供 **撤销**，点击后把刚创建的任务
  移入垃圾箱并刷新列表；AI 失败回落到规则创建时同样可以撤销，提示里会同时保留失败原因。
- 草稿未处理时按普通 `Enter` 会提示先添加或取消，不会绕过草稿重复建任务。
- 请求期间按钮显示「解析中」，输入框仍可编辑，不会锁住界面。
- 请求期间按钮右侧出现 **取消**，按 `Esc` 同样可以中止：renderer 通过 `ai:cancel` 让
  main 进程中止那次 `fetch`，不必等满 15 秒超时。取消后提示「已取消 AI 解析，输入内容已保留」，
  既不写库也不弹草稿；取消**不触发**自动重试。
- 迟到的结果一律丢弃：每次 AI 请求都带一个自增 `requestId`，取消或重新发起新请求后，
  旧请求的响应即使回来了也不会弹草稿；如果用户在等待期间改写了输入，结果同样被忽略并提示
  「输入已变化，已忽略上一次 AI 解析结果」，避免把上一条任务的解析结果套到新输入上。
- 解析进行中按普通 `Enter` 不再静默失败，而是提示「AI 正在解析，按 Esc 或点「取消」可中止」，
  不会绕过请求重复建任务；切换视图导致快速添加框卸载时，也会顺手中止进行中的请求。
- 结果会再次经过 `normalizeAiQuickAdd` 校验：非法日期/时间被丢弃，优先级夹到 0–3，
  标签去重。`recurrence` 会经过 `normalizeRecurrenceRule` 收敛：大小写、全角分号与
  `BYDAY` 顺序会被统一，`INTERVAL=0`、未知 `FREQ`、越界 `BYMONTHDAY` 等非法片段被丢弃；
  只剩非法规则时回落到本地规则。模型用中文写重复（如「每月最后一个周五」）也会用同一套
  规则翻译成 RRULE。`listName` 只有在用户输入中明确出现该清单名（忽略大小写与空白）时才采纳，
  防止模型按任务内容猜一个清单；未采纳时任务留在当前清单。采纳但清单已不存在时，
  回落到当前默认清单并提示。
- AI 结果会与本地 `parseQuickAdd` 结果合并：输入里的 `#标签`、`!高/中/低`、`~清单`
  是用户显式写出的确定性信息，AI 漏掉或改写时以规则解析为准，标题中残留的显式标记
  会被清掉；日期、时间、重复等自然语言字段优先采用 AI 结果，但 AI 返回 null 漏掉时
  会用规则解析补齐。例如模型只返回标题「交周报」，用户输入中的「明天下午3点」仍会
  保留为截止日期与时间，不会被丢掉。
- 本地规则解析同时补强了这些高频写法（AI 不可用时同样生效）：
  `下个月15号` / `本月20号`、`2027年1月1日`、`下个星期天`、`10点到11点`
  （取开始时间）、`每周一三五` / `每周二、周四`（多日 RRULE）、`每月最后一天`、
  `每月第一个周一` / `每月第2个周四` / `每月最后一个周五`（BYSETPOS）、
  `每季度` / `每半年`（MONTHLY + INTERVAL）、`3天后` / `2周后` / `3个月后`。
  `#工作，` 这类尾随标点、全角 `！高`，以及 `#工作!高~工作` 连写都能正确拆分；
  非法日期（如 `2026-02-30`）保持为标题而不是写库。
- **口语日期与时段**：`今晚` / `明早` / `明晚` / `昨晚` / `今晚上` 会拆成「日期词 + 时段词」
  再分别解析，`今晚8点` → 当天 20:00、`明早` → 次日 08:00、`昨晚` → 前一天 20:00；
  `每晚9点` / `每早8点` 补成「每天 + 时段」，重复为每天、时间为 21:00 / 08:00。
  只说时段、没说钟点时（`明天下午 开会`、`下午 评审`）按该时段的默认钟点落到截止时间：
  凌晨 06:00、早上/早晨 08:00、上午 09:00、中午 12:00、下午 15:00、傍晚 18:00、晚上/夜里 20:00，
  不再出现「有日期但没时间」的全天任务。`下午茶` / `晚上好` / `中午饭` 这类普通词语
  后面跟了成词的字时不会被当成时间吞掉。
- **相对时刻**：`30分钟后` / `半小时后` / `一小时后` / `两个小时后` / `15分钟之后`
  以当前时刻为基准，同时算出日期与时间（`90分钟后` 跨天会顺延日期），并从标题里移除。
  `30天后` 这类以天为单位的写法仍走日期规则，保持全天。
- **相对日期**：数量的中文写法同样生效——`三天后` / `两周后` / `三个月后` / `一年后` /
  `半年后`；`月底` / `本月底` / `下个月底` / `12月底` 落到对应月份最后一天，
  `月初` 类落到 1 号（已经过去时顺延到下一个 1 号，避免建出立即逾期的任务），
  `周末` / `本周末` / `下周末` 落到最近的周六（周日问「本周末」就是今天）。
- **周期 + 星期**：`每两周的周二` → `FREQ=WEEKLY;INTERVAL=2;BYDAY=TU`，
  `每2周的周一、周三` → `FREQ=WEEKLY;INTERVAL=2;BYDAY=MO,WE`，
  `每两周的周一到周五` 也会保留 `INTERVAL=2` 与五个星期；`的周二` 不会残留在标题里。
  另外补上 `每周末` → `FREQ=WEEKLY;BYDAY=SA,SU`、`每月底` → `FREQ=MONTHLY;BYMONTHDAY=-1`。
- 重复与时间同时出现时，首次日期跟着重复规则的第一次走：`每周五下午 总结` 落在下个周五
  15:00，而不是被「下午」默认成今天；只写了时间（`下午 开会`）才落在今天。
- 重复规则在界面和草稿下拉框里按语义展示：`FREQ=DAILY;INTERVAL=3` 显示「每3天」、
  `FREQ=WEEKLY;INTERVAL=2;BYDAY=MO,WE` 显示「每2周的周一、周三」、
  `FREQ=MONTHLY;BYDAY=FR;BYSETPOS=-1` 显示「每月最后一个周五」，
  不再笼统显示成「每天 / 每周」。
- **提前提醒**：`提前30分钟提醒`、`提前提醒我半小时`、`提前1小时通知我`、
  `提前一天提醒` 会被规则识别为提前量（分钟），从标题里移除，并在任务创建后写入
  `reminders` 表；`提前30分钟出发` 这类没有提醒动词的句子不会被误吞。
  AI 输出 `reminderMinutes`（“提前30分钟”=30、“提前1小时”=60、“提前一天”=1440），
  与规则互补：AI 漏掉时用规则补，AI 与规则都有时以 AI 为准；负数或超过 30 天丢弃。
  提前量按截止日期/时间换算，全天任务按当天 09:00 计算；提醒时间已过或任务没有
  截止日期时不创建“永不触发”的提醒，任务照常添加并在 toast 里说明原因。
  提醒可以直接在 AI 草稿的「提醒」下拉框里改成 5/15/30 分钟、1/2 小时或 1/2 天，
  清空截止日期会自动清空提醒。

提示词会带上当前时间、星期与全部可用清单名，并明确要求「只有输入中明确提到清单时才填写
`listName`，不要根据任务内容猜测」，同时要求原样保留 `#标签` / `!优先级` / `~清单`
显式语法，并给出 `reminderMinutes` 的常见换算，尽量让 AI 输出可直接落库的结构。
重复示例里补充了 `每两周的周二` → `FREQ=WEEKLY;INTERVAL=2;BYDAY=TU`；
口语时间要求模型换算成具体值（`今晚8点` → 当天 20:00、`明早` → 次日 08:00、
`月底` → 当月最后一天、`30分钟后` → 当前时间加偏移），只说时段时按与规则一致的
默认钟点（下午 15:00、晚上 20:00 等）填写，避免 AI 与本地规则给出两套不同答案。

### 3.2 AI 拆解子任务

入口：任务详情抽屉 →「子任务」标题右侧的 ✨ 按钮。

- 输入：主任务标题、备注、所属清单，以及**已有子任务标题**；提示词明确要求模型不要重复或改写已有子任务。
- AI 输出：`{"subtasks":[{"title":"...","priority":0}]}`，最多 10 条。
- 客户端会过滤掉与主任务或已有子任务同名（忽略大小写与空白）的条目，去重、去空、限制长度，
  然后展开「AI 拆解结果 · 可修改后添加」草稿：每条子任务都能改标题、调优先级、勾选/取消或删除，
  点「添加选中（N）」才批量写库。点「取消」或在标题框按 `Esc` 放弃草稿，不写库；
  草稿未处理时 AI 按钮不可用，避免重新解析覆盖用户改过的内容。
- 草稿确认时会再按当前列表过滤一次：如果草稿展示期间用户手动加了同名子任务，
  该条会被跳过，不会重复写入；全部条目都已存在时提示「请至少保留一个未添加过的子任务」。
- 创建成功后 toast 显示本次新增数量并提供 **撤销**，一次移除本批次创建的子任务。
  若 AI 不可用而使用规则拆解，提示里保留失败原因，撤销同样可用。
- 拆解请求期间 AI 按钮右侧出现 **取消**：renderer 通过 `ai:cancel` 中止 main 里那次
  `fetch`，不必等满超时。取消后提示「已取消 AI 拆解，未写入任何子任务」，既不写库也不弹草稿，
  且**不触发**自动重试。切换任务或关闭详情面板时也会自动中止进行中的拆解请求，
  迟到的结果按 `requestId` 丢弃，不会落到新任务或重新打开的面板里。
- 若模型返回的条目全部已存在，提示「AI 返回的子任务均已存在，未重复添加」，不会创建空任务，
  也不会弹草稿。
- 规则降级：按标题/备注中的换行、分号、逗号/顿号拆分，去掉 `-`、`*`、`1.` 等列表符号；
  同样跳过主任务与已有子任务同名条目；没有可拆内容时提示手动添加。规则结果是确定性的，
  仍保持一步添加（带撤销），不进入二次确认草稿。

### 3.3 AI 今日计划总结

入口：「今天」视图快速添加框下方的「AI 今日总结」卡片，点击「生成 / 刷新」才发请求，
不会在启动时自动调用。

- 输入：今日未完成/逾期任务、今日完成任务的标题、状态、优先级、截止日期/时间、清单
  与 `overdue` 标记，以及总数、完成数、逾期数。
- “今日完成”按完成时间的**本地日期**判断（数据库存 UTC ISO，不会因时区偏移把凌晨
  完成的任务算到前一天）；已完成任务只按完成时间纳入，不会因为截止日期是今天而被
  误计为“今日完成”。逾期标记逐条随任务发给 AI，便于生成更准确的建议。
- AI 输出：`{"summary":"...","highlights":["..."],"suggestions":["..."]}`。
- 生成期间按钮显示「生成中 3s」（已等待秒数），旁边出现 **取消**：中止那次 `fetch` 后提示
  「已取消 AI 总结生成，可随时重新生成」，卡片保留上一次结果；迟到的响应按 `requestId`
  丢弃，取消不重试。卡片卸载（切到其他视图）时同样自动中止请求，不在后台白等超时。
- 生成失败时卡片回落到本地统计，并保留 toast「重试」入口；重试会使用新的 `requestId`，
  旧响应不会被当成新请求的结果。
- 规则降级：使用本地统计生成确定性文案（完成/剩余/逾期数量、下一个时间点、
  高优先级任务、逾期任务处理建议）。

## 4. 失败重试与超时提示

只对**瞬时故障**自动重试一次（总共 2 次尝试，间隔 200ms），重试在 main 进程内完成，
renderer 只是多等这一小会儿，不会因此重复创建任务：

| 失败情况 | 判定依据 | 自动重试 | 用户看到的提示 |
| --- | --- | --- | --- |
| 连接被拒 / 网络中断 | `ECONNREFUSED`、`ECONNRESET`、`fetch failed` 等 | 是 | `连接不上 AI 服务（127.0.0.1:15721），请确认 CC Switch 已启动 · connect ECONNREFUSED（已自动重试 1 次）` |
| 服务限流 / 服务端错误 | HTTP 408、425、429、5xx | 是 | `AI 服务繁忙，请稍后再试 · AI 接口返回 500：…（已自动重试 1 次）` |
| 请求超时 | 超过 `aiTimeoutMs`，由 `AbortController` 中止 | 否 | `AI 请求超时（15 秒），可在设置里调大超时或换更快的模型` |
| 鉴权失败 | HTTP 401 / 403 | 否 | `AI 鉴权失败，请检查设置里的 Token（本机服务通常留空）` |
| 模型或参数错误 | HTTP 400 / 404 / 422 | 否 | `模型或请求不可用，请在设置页用「获取模型列表」逐字核对模型 ID` |
| 用户主动取消 | `ai:cancel` 中止 `fetch`，或 Esc /「取消」按钮（快速添加、今日总结、子任务拆解、设置页模型目录都支持） | 否 | 提示「已取消 AI 解析」/「已取消 AI 总结生成」/「已取消 AI 拆解」/「已取消获取模型列表」，不写库、不弹草稿、不改配置 |
| 只有 thinking、没有正文 | `stop_reason=max_tokens` 且正文为空 | 否 | 保留「AI 只返回了推理过程，正文为空（输出预算不足）」 |
| 返回结构无法识别 | 取到 JSON 但字段不合规 | 否 | `AI 返回内容无法解析，已按本地规则处理` |

超时**不重试**是刻意设计：超时已经用满了用户配置的等待时间，再重试一次会让按钮多转一倍，
而连接被拒、5xx 这类错误通常毫秒级返回，重试成本可以忽略。总尝试次数上限 3，
实现见 `src/main/ai-client.ts` 的 `withAiRetry`。

取消与超时都表现为 `AbortError`，客户端用“外部 signal 是否已中止”区分：
外部 signal（`ai:cancel`）中止 → `AiCanceledError`（文案「AI 请求已取消」），
`withAiRetry` 直接结束、不重试、不追加「已自动重试 N 次」；只有内部超时计时器中止
才提示「AI 请求超时」。失败分类里取消是独立的 `canceled` 类型，提示不会引导用户去调大超时。

取消覆盖四个入口，共用同一套 `requestId → AbortController` 注册表：快速添加用
`quick-add-N`、今日总结用 `summary-N`、子任务拆解用 `subtasks-N`、设置页模型目录用
`models-N`。今日总结与拆解在切换任务、关闭详情面板或卡片卸载时会**静默中止**（不弹提示），
关闭设置页时目录请求同样静默中止；用户主动点「取消」时才提示。
main 返回的 `warning` / `message` 使用 `AI_CANCELED_QUICK_ADD_HINT` /
`AI_CANCELED_SUMMARY_HINT` / `AI_CANCELED_SUBTASKS_HINT` / `AI_CANCELED_MODELS_HINT`
常量，renderer 与 main 不会各写一套文案。
今日总结与快速添加一样在按钮上显示「生成中 Ns」的已等待秒数，模型目录按钮显示
「获取中 Ns」，超时前能看到进度而不是界面卡住。

- 提示文案统一由 `src/shared/ai.ts` 的 `describeAiFailure` 生成：先说明原因（超时秒数、
  服务地址、HTTP 状态），再给出下一步（调大超时、启动 CC Switch、核对模型 ID、检查 Token），
  原始错误附在 `·` 之后便于排查；实际请求超过 1 次时追加「（已自动重试 N 次）」。
  原始错误已被提示覆盖时不会重复拼接。
- 快速添加的 AI 按钮在请求期间显示已等待秒数（`解析中 3s`），悬停提示当前超时上限，
  用户能分清「正在解析」和「界面卡住」。
- 今日总结、子任务拆解的失败 toast 带「重试」按钮，网络恢复后不用重新打开面板；
  快速添加失败时任务已按规则创建，因此只提示原因，不提供重试，避免重复建任务。
- 响应对象新增可选 `attempts` 字段：失败时为实际请求次数，`0` 表示因为关闭 AI 或空输入
  根本没发请求；请求成功（包括重试后成功）也能回报尝试次数，便于测试与后续埋点。
- 设置页「超时（毫秒）」下方写明：超时按单次请求计算、瞬时故障自动重试 1 次、超时不重试。

## 5. 降级策略

| 场景 | 行为 |
| --- | --- |
| `aiEnabled=false` | 不发请求。快速添加走 `parseQuickAdd`；AI 总结卡片与拆解按钮隐藏 |
| 服务未启动 / 连接被拒 | 快速添加用规则解析；拆解用标点/换行规则；总结用本地统计；toast 说明原因与提示地址，并自动重试 1 次 |
| 请求超时 | 同上，超时时间由 `aiTimeoutMs` 控制，默认 15 秒；提示里会写明超时秒数 |
| 非 2xx / 模型不存在 | 5xx 与 429 自动重试 1 次；4xx 不重试；错误摘要进入 toast 与 `warning` 字段 |
| 返回非 JSON 或字段缺失 | `parseAiJson` / `normalize*` 返回 null，按失败降级 |
| 只有 thinking、正文被 `max_tokens` 截断 | 同上；toast 提示「AI 只返回了推理过程，正文为空（输出预算不足）」 |
| 返回日期非法、优先级越界 | 只丢弃非法字段，保留其余合法结果，不整体失败 |
| 快速添加的清单名不存在 | 放入当前默认清单，并提示「未找到清单 X，已放入 Y」 |

所有 IPC 调用均在 `try/catch` 中执行，main 进程不会因 AI 异常崩溃；renderer 的
`try/finally` 会复位 loading 状态，保证按钮可再次点击。

### 6.1 快速添加准确率回归集

`tests/quick-add-regression.test.ts` 把“用户输入 → 最终落库字段”固化成可重复执行的回归集，
所有用例固定在同一时刻 `2026-11-05 周四 09:00`，避免相对日期随时钟漂移。

- **规则用例（83 条）**：覆盖相对日期、星期、跨年、月日、时间区间、重复、提前提醒、
  显式标签/优先级/清单、纯标题与非法日期，以及这一轮补强的口语时段（`今晚`/`明早`/`下午`）、
  相对时刻（`30分钟后`）、中文数量（`两周后`/`半年后`）、月界（`月底`/`下个月初`/`12月底`）、
  周末、`每两周的周二` 与 `每周末`。每条都精确断言 `title`、`priority`、`tags`、
  `listName`、`dueDate`、`dueTime`、`allDay`、`recurrence`、`reminderOffsetMin` 全部字段，
  未写出的字段按默认值比较，不会出现“只校验标题”的宽松通过。
- **AI 合并用例（28 条）**：用假 fetch 返回贴近真实模型的输出，覆盖 Markdown 代码块与
  前后解释、模型只返回标题、漏日期/时间/重复/提前提醒、没提清单却猜清单、显式提到清单、
  非法日期/时间/优先级/提前量、标题残留显式标记、字符串优先级、OpenAI `choices` 响应、
  AI 日期优先于规则、非法/中文 recurrence 的收敛与回落、每月第 N 个星期补齐，
  以及模型漏掉 `今晚`/`30分钟后`/`月底`/`每两周的周二` 时由规则补齐等场景，
  断言合并后的最终结果。
- **失败与重试**：非法 JSON、JSON 缺 title、只有 thinking 被 `max_tokens` 截断、401 不重试、
  500 重试一次后成功、连接失败重试后仍失败、超时提示秒数且不重试、空输入与关闭 AI
  不发请求，同时校验 `attempts` 计数。
- **请求契约**：只请求 `http://127.0.0.1:15721/v1/messages`，请求体 `model` 必须与默认
  模型 ID 逐字一致，`max_tokens` 使用快速添加预算，Token 为空时不发送 `authorization`。

新增解析能力时先在 `RULE_CASES` / `AI_CASES` 补一条用例，再改实现；日常可用
`npm run test:ai` 只跑 AI 相关测试。

### 6.2 AI 结果桌面端 E2E

`e2e/ai-quick-add.spec.ts` 用 Playwright 启动真实 Electron 应用，验证 AI 结果从
「模型返回」到「界面可操作」的完整链路，全部用例只连**本机回环地址上的假网关**
（`127.0.0.1` 随机端口），不发往任何外部服务：

- **草稿可编辑→添加→撤销**：假网关返回带 Markdown 代码块的 JSON，断言草稿中的
  标题、日期、时间、优先级正确；草稿展示期间任务数为 0；修改标题与优先级后点「添加」，
  列表出现编辑后的标题；点 toast「撤销」后任务被移除。
- **5xx 自动重试→规则降级→撤销**：假网关始终返回 500，断言实际收到 2 次请求、
  toast 同时含「AI 未能解析，已按规则添加…」「AI 服务繁忙」「已自动重试 1 次」，
  且没有弹出草稿；规则任务仍可通过 toast 撤销。
- **取消解析**：假网关延迟 2.5 秒返回，请求途中点「取消」，断言 toast 提示已取消、输入内容保留、
  迟到的响应不会弹出草稿也不会建任务，且只发出过一次请求（取消不重试）。
- **今日总结可取消**：假网关延迟 2.5 秒返回，点「取消 AI 总结生成」后断言 toast 提示已取消、
  迟到的总结不会渲染到卡片、按钮回到「生成」可用状态，且只发出过一次请求。
- **关面板中止拆解**：延迟返回的拆解在关闭详情面板（组件卸载）时被中止，重新打开任务后
  既没有迟到的草稿也没有写入子任务，假网关只收到一次请求。
- **改写输入后丢弃旧结果**：假网关延迟返回旧输入的解析结果，等待期间把输入改成另一句话，
  断言提示「输入已变化，已忽略上一次 AI 解析结果」、不弹草稿、不建任务、输入保持新内容。
- **超时不重试**：把 `aiTimeoutMs` 调到 1000，假网关延迟 2.5 秒；断言 toast 写明
  「AI 请求超时（1 秒）」且没有「已自动重试」字样，任务按规则创建后可撤销，假网关
  只收到 1 次请求。
- **关闭 AI**：`aiEnabled=false` 时断言快速添加的 AI 按钮、取消按钮与今日总结卡片都隐藏；
  普通 `Enter` 仍按规则建任务，且假网关没有收到任何请求。
- **今日总结失败后重试**：假网关前 2 次（首次 + 自动重试）返回 500，断言卡片回落到本地
  统计且带失败说明；点 toast「重试」后第 3 次成功，断言卡片切换为 AI 文案、失败说明消失。
- **子任务拆解失败降级**：假网关始终 500，主任务备注写成「整理数据；撰写结论」，
  断言按规则一步创建 2 个子任务、toast 同时含「AI 拆解不可用，已按规则添加」与
  「AI 服务繁忙」，撤销后子任务清空（规则结果不进入二次确认草稿）。
- **模型目录即选即用**：设置页点「获取模型列表」请求本机 `GET /v1/models`，断言目录中
  没有当前模型时出现核对提示；从下拉框选中目录里的 id 后提示消失，保存后快速添加的
  `POST /v1/messages` 请求体 `model` 与选中 id 逐字一致，且 Token 为空时不带 `authorization`。
- **模型目录加载可取消**：假网关延迟 2.5 秒返回目录；点「取消获取模型列表」后断言 toast
  写明已取消、按钮恢复可用，等过延迟后下拉框仍不出现，且只发出过一次目录请求。
- **模型目录失败后重试**：假网关前 2 次（首次 + 自动重试）返回 500，断言 toast 含
  「获取模型列表失败」「AI 服务繁忙」「已自动重试 1 次」；点 toast「重试」后第 3 次成功，
  下拉框出现且包含目录里的 id。
- **今日总结**：断言 AI 的 `summary`、`highlights`、`suggestions` 渲染，且不显示
  「已回落到本地统计」说明。
- **子任务拆解**：从详情面板触发，断言先出现可编辑草稿且暂不写库；改标题、取消勾选一条后点
  「添加选中」，断言只写入选中的子任务、toast 显示新增数量，批量撤销后清空。
- **请求契约**：除模型目录用例外，每次请求都是 `POST /v1/messages`，`model` 与
  `AI_DEFAULT_MODEL` 逐字一致，`max_tokens` 分别等于快速添加 1200、今日总结 1600、
  子任务 1600 的预算；Token 为空时不带 `authorization`。模型目录用例则验证用户在
  设置页选中的 id 被逐字带入请求体。

每个用例通过 `TICKFLOW_USER_DATA` 指向 `os.tmpdir()` 下的一次性目录，启动独立数据库，
结束后删除，**不会读写真实用户数据**。主进程在 `requestSingleInstanceLock` 与
`initDatabase` 之前应用该环境变量（见 `src/main/index.ts`），因此 E2E 也不会与
正在运行的正式实例抢单实例锁。

新增 AI 结果交互时，优先在 `e2e/ai-quick-add.spec.ts` 扩展假网关返回与断言；
若只想验证纯函数或组件行为，仍放在 `tests/` 下的 Vitest 用例，运行更快。

## 7. 隐私与边界

- 只有用户主动触发 AI 按钮/总结时才发送任务内容；普通快速添加与启动流程不联网。
- 发送内容限于当前输入句、主任务标题/备注、该任务已有子任务标题、今日任务摘要，
  不包含数据库全量数据。
- Token 仅存本机数据库，请求只发往配置的 `aiBaseUrl`；不会自动切换第三方地址。
- E2E 使用 `TICKFLOW_USER_DATA` 指向临时目录，并通过 `127.0.0.1` 随机端口假网关响应，
  不接触真实用户数据库、不访问外部网络（见 6.2）。
- AI 生成的时间、清单和子任务都会经过本地校验后再写库，AI 不能直接修改数据库。
- 取消只中止本机发起的那一次请求（按 renderer 生成的 `requestId` 定位），请求结束后注册表立即清空，
  不会残留 controller 或跨请求误取消。快速添加、今日总结、子任务拆解共用这套注册表；
  切任务、关面板等自动中止不会弹出提示，也不会影响其他并行请求。

## 8. 离线语音输入（快速添加）

入口：快速添加栏输入框右侧的麦克风按钮。语音只负责把话转成文字并追加到输入框，
日期、时间、标签、优先级、重复与提前提醒仍走原有「规则解析 + AI 解析」流程，不新增落库路径。

### 8.1 录音与识别链路

1. renderer 点击麦克风 → 先调用 `ai:asr-status` 做一次本地环境自检（只 stat 文件）：
   缺少脚本/Python/模型时直接提示缺哪一项，**不申请麦克风、不录音**，避免说完一句才失败；
   自检接口本身异常或旧 preload 没有这个方法时放行，由后续转写报具体错误。
2. 环境可用才 `getUserMedia({ audio: true })` 申请麦克风；
   main 的 `setPermissionRequestHandler` 只放行 `media`，其余权限继续拒绝。
3. `MediaRecorder` 每 250ms 收集一个数据块，按钮实时显示「录音中 Ns」；
   最长 60 秒，到点自动停止并进入识别，避免超长音频占内存或卡住 IPC。
4. 停止后把 `webm/opus` 字节通过 `ai:transcribe` 发给 main，并带 `requestId`（`voice-N`）；
   main 用 ffmpeg 转成 16kHz 单声道 WAV，再调用本机 Python + vosk 转写。
5. 识别文字用 `appendTranscript` 追加到输入框（已有内容保留，用空格分隔），
   用户检查或继续编辑后再按 Enter / Ctrl+Enter 建任务。

录音与转写都在本机完成，不联网。Python、vosk 与 ffmpeg 是可选的本地依赖；
找不到时点麦克风会在录音前给出「离线语音识别不可用：缺少 …」的具体原因与 **重试**，
键盘输入与普通快速添加不受影响。

### 8.2 误触、权限与失败降级

| 场景 | 行为 |
| --- | --- |
| 点击麦克风时离线环境不完整 | 按钮短暂显示「检查中」，不申请麦克风；toast 说明缺少脚本/Python/模型，并提供 **重试**（重新自检，环境补齐后直接进入录音） |
| 环境自检 IPC 异常 / 旧 preload 无 `asrStatus` | 放行录音，不因自检接口本身失败而禁用语音入口；真实问题仍由转写错误兜底 |
| 检查环境期间切换视图 / 组件卸载 | 递增启动 token，迟到的自检结果直接丢弃，不再申请麦克风 |
| 点击麦克风后等待系统授权（`getUserMedia`） | 按钮显示「授权中」并变为可取消；再点一次即放弃本次启动，迟到的麦克风流会被主动停掉 |
| 授权等待超过 15 秒（系统弹窗挂起） | 提示「等待麦克风权限超时」，按钮恢复并给 **重试**；之后才返回的流同样会被停掉，不会偷偷录音 |
| 等待授权期间切换视图 / 组件卸载 | 递增启动 token 并停掉迟到的麦克风流，不留下亮着的麦克风 |
| 录音短于 0.6 秒 | 判定为误触，直接丢弃，提示「录音太短…」，不发起转写 |
| 用户点击停止时录音已停止 | 忽略重复点击，不会重复转写 |
| 麦克风权限被拒绝（`NotAllowedError` / `PermissionDeniedError`） | 提示「麦克风权限被拒绝，请在系统设置里允许 TickFlow 使用麦克风」，不提供无意义的重试 |
| 没有麦克风（`NotFoundError`） | 提示连接录音设备，可点 toast「重试」 |
| 麦克风被占用（`NotReadableError` / `TrackStartError`） | 提示关闭占用程序后重试，toast 带 **重试** |
| 系统安全策略 / 参数不支持 / 启动中断 | 分别给出对应提示，原始错误保留在冒号后；除安全策略外均提供 **重试** |
| 浏览器不支持 `mediaDevices` 或 `MediaRecorder` | 提示「当前环境不支持录音，请改用键盘输入」 |
| 录音中麦克风被拔出（track `ended`） | 丢弃本次录音并提示「麦克风连接中断」，不转写半截音频 |
| 录音过程中组件卸载（切换视图） | 停止所有 track、丢弃 onstop 结果，不发起转写 |
| 录音中 / 识别中 / 等待授权 / 检查环境时按 `Enter` | 提示「正在录音，先结束录音再添加」等，不会把半截输入建成任务；AI 按钮同步置灰 |
| AI 解析进行中或 AI 草稿未处理时点麦克风 | 提示先把 AI 解析处理掉，不申请麦克风、不启动录音，避免两套结果抢同一个输入框 |
| `MediaRecorder` 报错或录音器启动失败 | 丢弃录音、提示「录音中断」等具体原因，按钮立即恢复，并提供 **重试** 重新申请录音；即使 `stop()` 再抛错也会复位按钮，不会卡在「录音中」 |
| 没有数据块 / 录音过大（>24 MB） | 不调用外部进程，提示重新录音或缩短到 60 秒内 |
| 空音频 / 已取消的请求 | main 直接返回人话，不启动 ffmpeg 或 Python |
| ffmpeg 不存在 / 转码失败 / 转码超时 | 分别提示缺少 ffmpeg、转码失败详情、转码超时（20 秒） |
| Python 不存在 | 提示「找不到语音识别运行时（Python），请在设置里填写路径」 |
| 缺少 vosk 依赖 | 从 Python stderr / JSON 中识别 `ModuleNotFoundError`，提示「语音识别环境缺少 vosk」 |
| 识别超时（转写子进程 60 秒） | 提示转写超时并修正为可重试；renderer 侧另有 90 秒总超时兜底（大于 main 的 ffmpeg 20 秒 + 转写 60 秒，保证先拿到 main 的具体错误而不是前端先取消） |
| 识别失败 / 没听清（空结果） | 提示原因并给 **重试**，直接复用同一段录音，不用重新录；同一时刻只允许一次转写，连点重试不会并行启动 |
| 转写 IPC 通道异常（main 崩溃 / 调用失败） | 提示「语音识别失败：<原始原因>；可在设置 → 语音输入（离线）里检查环境」并提供 **重试**，不会误报成「打不开麦克风」 |

### 8.3 取消与超时

- 识别中按钮显示「识别中 Ns」，点击同一按钮即 **取消**：renderer 调 `ai:cancel`
  中止 main 里那次请求，`runProcess` 会 kill ffmpeg / Python 子进程并清理临时目录。
- 点击麦克风后、真正录音前，按钮先显示「检查中」做本地环境自检：再点一次即取消
  （提示「已取消录音启动」）；自检通过后自动进入「授权中」，不需要二次点击。
- 点击麦克风后、系统授权返回前，按钮显示「授权中」：再点一次即取消启动，
  提示「已取消录音启动」；15 秒仍未返回则判定权限弹窗挂起，给出超时提示与 **重试**。
  `getUserMedia` 无法真正中止，所以用启动 token 让迟到的流在到达时立即 `track.stop()`，
  取消、超时、切换视图都不会让麦克风在后台保持开启。
- 取消后 toast 提示「已取消语音识别」，迟到的识别结果按 `requestId` 丢弃，
  不会覆盖用户已经改过的输入；按钮立即恢复。
- 识别成功时 toast 提示「已追加语音文字「…」」并提供 **撤销**：输入没被改动时
  原样恢复到追加前；用户又补了标点或新内容、但识别文字仍在末尾时只摘掉末尾这一段；
  输入已经改得认不出这段文字时不做任何删除，只提示「输入已变化，未撤销语音文字」。
- 识别失败、返回空结果或 IPC 报错时，toast 提供 **重试**：复用同一段录音重新转写，
  不用重新说一遍；重试会生成新的 `requestId`，旧响应不会落到新请求上。
- renderer 等待上限 90 秒（`VOICE_TRANSCRIBE_TIMEOUT_MS`），超时后自动取消 main 请求，
  toast 提供 **重试**（复用同一段录音），不用重新录。main 两步子进程上限
  `VOICE_FFMPEG_TIMEOUT_MS`（20 秒）与 `VOICE_ASR_TIMEOUT_MS`（60 秒）同样定义在
  `src/shared/voice.ts`，三者保持 20 + 60 < 90 的预算关系，单元测试会锁住这个不变量。
- 识别期间仍可编辑输入框；取消/超时**不写库**，也不影响 AI 解析的取消注册表。

### 8.4 配置与自检

设置项（存本机 SQLite，均可留空）：

| 设置键 | 默认值 | 说明 |
| --- | --- | --- |
| `asrPython` | 空 | Python 可执行文件路径；留空依次尝试环境变量与常见路径 |
| `asrModel` | 空 | vosk 模型目录；留空同样自动探测 |

自动探测顺序：设置项 → `TICKFLOW_ASR_PYTHON` / `TICKFLOW_ASR_MODEL` → 开发机常见路径。
设置页「语音输入（离线）」提供两个路径输入框与 **检查语音环境**，会保存配置后调用
`ai:asr-status`，明确告知缺少脚本、Python 还是模型；找不到时逐项说明，不弹笼统错误。
